Module 07 — Cryptography Foundations

About Cryptographic Hash Functions

A structured educational reference covering the theory, mathematical properties, attack methodologies, and modern industry standards for secure credential storage.

Core Theory

What is a Cryptographic Hash Function?

A cryptographic hash function H is a deterministic algorithm that maps an arbitrary-length byte sequence M to a fixed-length bit string D (the digest or fingerprint):

H : {0,1}* → {0,1}n

Unlike symmetric or asymmetric encryption, hashing is a one-way trapdoor function. There is no key and no inverse operation. The output is a fixed-size, opaque digest that leaks no information about the original input. SHA-256 produces n = 256 bits (2⁶⁴ possible inputs map to each possible output, by the pigeonhole principle).

The Four Essential Security Properties

01

Determinism

The same input message always produces the exact same digest output. This property is required for password verification — the same password must always hash to the same value to allow comparison.

SHA256("hello") → 2cf24dba...
Always and forever.
02

Pre-image Resistance

Given only the digest D, it must be computationally infeasible to find any message M such that H(M) = D. This is the "one-way" property — hashing cannot be reversed.

Given 2cf24dba...
Cannot recover "hello".
03

Collision Resistance

It must be computationally infeasible to find any two distinct messages M₁ ≠ M₂ such that H(M₁) = H(M₂). MD5 is broken because practical collisions can be found in seconds.

For SHA-256: finding a collision requires ~2¹²⁸ operations.
04

Avalanche Effect

A single-bit change in the input should cause each output bit to flip with probability ½ (Strict Avalanche Criterion). This ensures no information about the plaintext leaks through the hash.

Changing "a" → "b" flips ~128 of 256 output bits.

Password Attack Methodologies

🔨

Brute-Force Attack

Exhaustively tries every possible character combination of increasing length until the correct password is found. Effectiveness depends entirely on attacker throughput and password entropy.

MD5: ~100 billion/sec on GPU
Defense: High-entropy password + slow hash function
📖

Dictionary Attack

Tests millions of common passwords from leaked databases (e.g., RockYou: 14 million passwords) or word lists. Extremely effective against passwords containing real words or common patterns.

Cracks most common passwords in <1 second
Defense: Avoid dictionary words; use random passphrases
🌈

Rainbow Table Attack

Uses precomputed tables of (plaintext → hash) pairs, trading storage space for computation time. A table covering all alphanumeric 8-char SHA-256 hashes fits on a 100TB drive.

Lookup time: O(1) for unsalted hashes
Defense: Unique cryptographic salt per password
⏱️

Timing Side-Channel Attack

Exploits differences in comparison time between string operations. By measuring microsecond response time variations, an attacker can reconstruct a valid hash character-by-character.

Works against naive `==` string comparison
Defense: hmac.compare_digest (constant-time comparison)
💉

SQL Injection

Injects malicious SQL syntax into form inputs to manipulate database queries. Can bypass authentication entirely: username = ' OR 1=1--.

Can grant access to any account without knowing the password
Defense: Parameterized queries (? placeholders)
🎭

Credential Stuffing

Automatically tests credentials leaked from one service breach against other services. Succeeds because ~85% of users reuse passwords across multiple accounts.

Billions of leaked credential pairs exist publicly
Defense: Unique password per service + 2FA
